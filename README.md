# Escape the Backrooms 3D — онлайн через Firebase Realtime Database + GitHub Pages

Проект перенесён с собственного Node.js/Socket.IO сервера (Render) на **бесплатный стек**:
- **Хостинг статики**: GitHub Pages (или Firebase Hosting, если хотите)
- **Мультиплеер/реалтайм**: Firebase Realtime Database
- **Сервера нет совсем!** Логика ИИ и голосования работает у **хоста** комнаты (игрока, который её создал). Если хост выйдет — лобби закроется.

## 🚀 Что сделано для экономии трафика и скорости

| Оптимизация | Экономия |
|---|---|
| Все имена полей в Firebase — 1–2 буквы (`n`, `x`, `z`, `M`, `Kc`, `tp/a`...) | меньше JSON на каждом обновлении |
| Координаты округляются до **1 знака** после запятой (≈40 см) | в ~3 раза меньше цифр на позицию |
| Позиция шлётся **не чаще чем раз в 150 мс** (~6.5 раз/сек) | против 60 раз/сек в старой версии |
| Позиция шлётся **только если она реально изменилась** после округления | при простое 0 трафика |
| В карте не передаётся сетка стен — она генерируется на каждом клиенте **детерминированно по seed** | -100% трафика на карту |
| Firebase подписывается только на изменяющиеся ветки (`value` events), а не шлёт весь стейт | встроено в SDK |
| Three.js и Firebase SDK грузятся через **jsDelivr** (CDN, лучше работает в РФ, чем firebaseio/google напрямую) | быстрая загрузка в России |

## ⚠️ Доступность в России (важно!)

Firebase Realtime Database **работает в России**, но есть нюансы:

1. **Выбирайте регион БД `europe-west1` (Бельгия)** при создании базы — это самый быстрый и стабильный пинг из РФ. Если выберете США (`us-central1`) — будет задержка 150–250 мс.
2. **CDN для SDK** уже заменён на `cdn.jsdelivr.net` (он открывается у всех крупных российских провайдеров). Если `jsdelivr` вдруг не открывается у вас, замените в `index.html` на `https://unpkg.com/firebase@9.23.0/...` или на локальную копию.
3. **Домен базы** `<project>.europe-west1.firebasedatabase.app` — на домены `*.firebaseio.com` иногда бывают проблемы, `*.firebasedatabase.app` работает стабильнее.
4. Если доступа к Firebase *вообще нет* (у некоторых корпоративных сетей), вам поможет VPN (WireGuard/Outline) или прокси. Для большинства домашних и мобильных провайдеров (Ростелеком, Yota, МТС, Теле2, Билайн) Firebase работает без VPN.
5. **GitHub Pages** (`<user>.github.io`) в России открывается стабильно. Если вдруг нет — можно задеплоить статику на Firebase Hosting или на Cloudflare Pages.

## 📝 Пошаговая инструкция по подключению

### Шаг 1. Создаём проект Firebase

1. Откройте https://console.firebase.google.com/
2. Нажмите **Добавить проект** (Add project)
3. Введите имя проекта (например, `backrooms-game`), отключите Google Analytics (не нужно), нажмите **Создать проект**.
4. На следующем экране (Project Overview) нажмите иконку **`</>`** (Web app).
5. Введите имя приложения (любое, например `web`), **не ставьте** галочку "Also set up Firebase Hosting" (мы используем GitHub Pages), нажмите **Register app**.
6. Скопируйте объект `firebaseConfig` — он выглядит так:
   ```js
   const firebaseConfig = {
     apiKey: "AIzaSy...",
     authDomain: "backrooms-game.firebaseapp.com",
     databaseURL: "https://backrooms-game-default-rtdb.firebaseio.com",
     projectId: "backrooms-game",
     storageBucket: "backrooms-game.appspot.com",
     messagingSenderId: "123456789",
     appId: "1:123456789:web:abc123"
   };
   ```
7. Нажмите **Continue to console**.

### Шаг 2. Включаем Realtime Database (европейский регион!)

1. В левом меню консоли выберите **Build → Realtime Database**.
2. Нажмите **Create database**.
3. В выпадающем списке **вместо США выберите `eur3 (Europe-West)`** — это критично для скорости из РФ. Нажмите Next.
4. На экране Security rules выберите **Start in test mode** (временное разрешение на чтение/запись), нажмите Enable.
5. ⚠️ **Обязательно замените правила после теста!** Перейдите во вкладку **Rules**, вставьте содержимое файла `database.rules.json` из этого проекта (он уже лежит рядом с `index.html`), нажмите Publish.

   > Эти правила не дают игрокам удалять чужие лобби и валидируют формат данных. Это НЕ идеальная защита от читеров, но для небольшой игры с друзьями хватает. Анонимная аутентификация в этой демо-версии отключена (чтобы не усложнять инструкцию).

6. Вернитесь в Project Overview и проверьте, что у `databaseURL` теперь вид с `https://<project>-default-rtdb.europe-west1.firebasedatabase.app` (иногда Firebase по умолчанию генерирует US-URL — **поменяйте его в вашем `firebaseConfig` на европейский!** Найдите его, кликнув Realtime Database → он виден как адрес базы на вкладке Data).

### Шаг 3. Вставляем конфиг в index.html

1. Откройте `index.html` в любом редакторе (VS Code, Notepad++ или даже Блокнот).
2. В самом начале `<script>` блока найдите:
   ```js
   const firebaseConfig = {
       apiKey: "ВСТАВЬТЕ_API_KEY",
       ...
   };
   ```
3. Замените на ваш `firebaseConfig` из шага 1.6.
4. Убедитесь, что `databaseURL` указывает на **europe-west1** (см. пункт выше). Сохраните файл.

### Шаг 4. Проверяем локально (опционально)

Любым простым HTTP-сервером из папки игры, например:
```bash
# Python 3
python3 -m http.server 8080
# или Node
npx serve .
```
Откройте http://localhost:8080 и нажмите "Играть онлайн" — список лобби должен загрузиться из Firebase (изначально он будет пуст).

### Шаг 5. Публикуем на GitHub Pages

1. Зарегистрируйтесь/зайдите на https://github.com.
2. Создайте новый репозиторий (**New repository**):
   - Repository name: любое, например `backrooms-game`
   - Public (чтобы GitHub Pages работал бесплатно)
   - Не ставьте галочку README/.gitignore
3. Нажмите **…or create a new repository on the command line** и выполните в папке с игрой:
   ```bash
   cd /path/to/game   # папка, где лежат index.html и firebase-net.js
   git init
   git add index.html firebase-net.js database.rules.json README.md
   git commit -m "online via firebase rtdb"
   git branch -M main
   git remote add origin https://github.com/<ВАШ_GITHUB>/backrooms-game.git
   git push -u origin main
   ```
   (либо можно просто перетащить файлы мышкой в веб-интерфейс GitHub в раздел "uploading an existing file")
4. После пуша зайдите в репозиторий на GitHub → **Settings** → **Pages** (в левом меню).
5. Source: **Deploy from a branch**, Branch: **main**, папка **/ (root)**, нажмите **Save**.
6. Через 1–2 минуты игра будет доступна по адресу:
   ```
   https://<ВАШ_GITHUB>.github.io/backrooms-game/
   ```
   GitHub сразу напишет этот адрес на странице Pages.

### ❗ Примечание: Firebase по умолчанию блокирует запросы с других доменов

Нужно добавить домен GitHub Pages в список разрешённых:
1. В консоли Firebase: **Authentication → Settings → Authorized domains** (даже если Auth не включён, список работает для веба).
2. Нажмите **Add domain** и добавьте:
   - `<ваш_юзер>.github.io`
   - (для теста) `localhost`
3. Сохраните. Без этого при открытии игры с GitHub Pages вы увидите ошибку в консоли `auth/domain-not-authorized`.

## 🎮 Как работает онлайн после деплоя

1. Игрок открывает сайт → нажимает "Играть онлайн".
2. Кто-то создаёт лобби → он становится **хостом**.
3. Другие видят лобби в списке, входят.
4. Хост жмёт "Начать игру" → начинается голосование (15 сек режим + 15 сек сложность).
5. Карта генерируется на хосте с помощью `seed`, `seed` отправляется в БД — **у всех клиентов карта одинаковая**, без передачи массива стен.
6. Дальше:
   - Каждый игрок отправляет свою позицию в Firebase раз в 150 мс (только если координаты поменялись после округления).
   - Хост (и только он!) двигает ИИ-монстра и обрабатывает укусы в `startHostGameTicker()`.
   - В режиме "Монстр" самим монстром управляет случайный игрок — он двигает модель и шлёт позицию в `/M/`.
7. Сбор папок: клиент при подходе к папке пишет транзакцию в `/K/<idx>/a = false` и `Kc++`. Победа при выходе: `/w = 'survivors'`. Победа монстра: `/w = 'monster'`.
8. При закрытии вкладки игрока его запись в `/P/<uid>` автоматически удаляется через `onDisconnect().remove()`. Если это был хост — лобби исчезает целиком.

## 🧰 Возможные проблемы и решения

| Проблема | Решение |
|---|---|
| Ошибка `firebaseConfig не настроен` | Вы не вставили свой конфиг в `index.html` (шаг 3). |
| Ошибка `PERMISSION_DENIED` | Забыли применить `database.rules.json`; либо база в test mode истекла (30 дней). |
| Ошибка `auth/domain-not-authorized` | Добавьте домен GitHub Pages в Authorized domains (шаг 5). |
| Высокий пинг/тормоза | Проверьте, что база в `eur3 (europe-west1)`. Если в `us-central1` — создайте новую базу в Европе. |
| firebase не грузится (белый экран) | Замените `cdn.jsdelivr.net` на `unpkg.com` в строках подключения SDK. |
| Все вылетели, лобби исчезло | Создатель лобби (хост) закрыл вкладку — это нормально, хост является сервером. |
| ИИ-монстр не двигается | В обычном режиме ИИ считается только на хосте. Если хост на слабой связи — обновления М редкие. |

## 📁 Структура проекта

```
game/
├── index.html         # вся игра (3D, UI, оффлайн-режим + адаптер в Firebase)
├── firebase-net.js    # сетевой слой на Firebase Realtime DB (сжатие, троттлинг, хост-логика)
├── database.rules.json  # правила безопасности БД
└── README.md          # эта инструкция
```

Старый файл `server.js` и `package.json` для Node.js/Express/Socket.IO **больше не нужны** — сайт полностью статический и работает без бэкенда. При желании вы можете запустить свой выделенный сервер для России и улучшить синхронизацию, но для игры с друзьями бесплатного Firebase+GitHub Pages хватает.
